# Core library Phase 1: remaining child issues of #65

Goal: finish `packages/core` per `docs/spec/core-api.md` and `docs/spec/file-format-v2.md` by landing #69 (anchoring), #70 (immediate writes), #72 (validation) and #71 (drafts and rounds), one PR each. #66–#68 are already merged.

Acceptance criteria (from the child issues):
- [x] #69 `anchors(threads, { overrides })` ports the prototype's scenarios as tests on real temp repos. The 3 known misses (5f, 7c, 8e) are recorded as expected results. 200 threads anchor in < 2 s.
- [x] #70 `createThread`, `reply`, `resolve`, `reopen` and `humanAuthor`, with tests first using pinned `now`/`random`. Files match the spec byte for byte, load back through `load()`, and the snapshot line count is right at file edges.
- [x] #72 `check()` and `schema/{thread,message,round,push}.schema.json`, with one fixture per rule asserting `code`, `path` and severity. The subset validator rejects unsupported keywords. `check()` never throws for content problems.
- [x] #71 drafts API and `submitRound`: N drafts give N messages, 1 round file and an empty `drafts/`. An interrupted submit is recoverable and leaves no draft lost. `.lhr/drafts/` is gitignored.
- [x] `npm test` is green in each PR.

Design:
- **One branch and PR per issue.** #69, #70 and #72 branch from `origin/main` and run in parallel in isolated worktrees. #71 is stacked on #70's branch, because it reuses anchor capture and the write helpers.
- **New modules, minimal shared edits:** `src/anchoring.ts` (#69), `src/write.ts` + `src/capture.ts` (#70), `src/check.ts` + `src/schemaCheck.ts` + `schema/*.json` (#72), `src/drafts.ts` (#71). Each PR adds its methods to `LhrTree`/`Tree` in `tree.ts` and its exports to `index.ts`. These shared edits are small, and any conflicts get resolved at rebase time. That is cheaper than serialising the work.
- **Writes** go through `serializeFrontmatter`. File creation uses exclusive mode (`flag: "wx"`), so nothing is overwritten (spec: no in-place edits outside `drafts/`). IDs come from `Tree.newId()` / `newMessageFileName()`, which are already injectable.
- **Anchoring** is a port of `prototypes/re-anchoring/reanchor.prototype.mjs` (branch `origin/prototype/re-anchoring`) into typed TS. It keeps one diff per file per call (a per-call cache keyed by blob and path), and reads blobs through the existing `GitBatch`.
- **Validation** has a hand-rolled checker for `required`, `type`, `enum` and `pattern`, plus the structural keywords `$schema`, `$id`, `title`, `description`, `properties` and `additionalProperties`. It throws on any other keyword when a schema loads. No new dependency.
- **Drafts gitignore (decision):** the core can't count on any other component creating `.lhr/`. So the first draft write creates `.lhr/drafts/.gitignore` containing `*`, which is self-contained. `check()` and `read` ignore `drafts/.gitignore` and `drafts/.submitting`.
- **Alternatives rejected:** one big PR (the issue asks for one per child), adding ajv (the issue forbids dependencies), and stacking everything serially (slower, with no correctness gain).
